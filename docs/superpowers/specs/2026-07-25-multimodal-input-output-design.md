# AutoForge 多模态输入输出设计

日期：2026-07-25
状态：已获用户逐段批准

## 1. 目标

在现有统一聊天入口中补齐图片、音频和视频的输入与输出链路，同时保留文本、工具调用、工作流执行和供应商切换能力。

本期成功标准：

- OpenRouter 支持图片、音频、视频输入和输出。
- DeepSeek 继续支持文本聊天；使用媒体时在本地明确提示不支持，不发送供应商请求。
- 用户可通过附件按钮、拖拽和粘贴剪贴板图片添加输入资产。
- 用户在自适应工具栏中选择自动、文本、图片、音频或视频输出。
- 图片、音频和视频结果以内联消息块展示。
- 视频生成任务跨应用重启继续轮询并在完成后下载到本地。
- 所有媒体资产保存在应用管理的本地目录；删除会话时一并删除。
- 文件字节、绝对路径和 Base64 不进入 Renderer 状态、普通 IPC 响应或 SQLite 消息 JSON。

## 2. 非目标

本期不包含：

- 独立媒体库或跨会话复用。
- 云同步、媒体分享或外部托管。
- 图片编辑、音视频剪辑、转码或波形分析。
- DeepSeek 多模态支持；其公开 API 当前只接入文本、推理和工具调用。
- 视频 Webhook 服务；桌面端采用持久化轮询。
- 直接内联 SVG；SVG 仅可作为文件保存或在系统中打开。
- 真实付费媒体生成作为 CI 的组成部分。

## 3. 已确认的产品决策

### 3.1 范围

- 同时支持多模态输入和输出，而不仅是模型输出。
- 所有能力使用现有聊天页面，不新增独立“创作”页面。
- OpenRouter 承担多模态能力；DeepSeek 保持文本。

### 3.2 本地资产生命周期

- 上传文件与生成结果复制或下载到应用本地媒体目录。
- 资产归属当前会话。
- 删除会话时删除该会话的所有媒体资产和未完成生成任务。
- 不保留指向用户原始文件的长期引用。

### 3.3 输入限制

- 每条消息最多 5 个附件。
- 图片单个不超过 20 MB。
- 音频单个不超过 50 MB。
- 视频单个不超过 200 MB。
- 单次输入总量不超过 250 MB。
- 生成结果单个不超过 500 MB。
- 超限请求在读取、编码和供应商调用前失败。

### 3.4 生成参数默认值

- 图片：1 张、自动画幅、1K、PNG。
- 音频：模型默认音色、MP3。
- 视频：5 秒、720p、自动画幅、默认不生成伴随音频。
- 参数控件只展示模型或端点实际支持的值。
- 用户修改的生成参数只保存在当前会话，不成为全局默认。

### 3.5 交互

- 使用自适应工具栏。
- 默认只显示附件和输出类型。
- 选择图片、音频或视频后，再显示对应参数入口。
- “自动”根据模型能力选择输出类型；用户可手动覆盖。
- Nano Banana Pro 等主要图像模型默认选择图片。
- 多输出模型首次使用时要求用户明确选择一次，此后记住当前会话选择。

## 4. 当前实现边界

现有链路只支持：

- `ModelStreamEvent` 中的文本增量、工具调用、完成和用量。
- `ChatBlock` 中的文本、推理状态、工作流、执行、审批和错误。
- `messages.blocks_json` 中的小型 JSON 消息块。
- Renderer 中的文本与工作流组件。

当前 OpenRouter Chat 流会忽略图片等媒体字段。视频生成也不能复用 Chat 流，因为 OpenRouter 视频 API 是提交、轮询、下载三段式异步协议。

## 5. 总体架构

采用“统一媒体资产层 + 模型能力路由”。

### 5.1 Renderer

Renderer 只负责：

- 展示附件、生成参数和媒体消息块。
- 持有资产 ID、媒体类型、不可变元数据、状态和安全预览地址。
- 调用受限 Preload API。

Renderer 不接收：

- 真实文件路径。
- API Key。
- 文件 Base64。
- 供应商原始错误体。
- 未校验的远程媒体 URL。

### 5.2 Preload

Preload 提供类型化媒体桥：

- 打开附件选择器。
- 导入拖拽文件。
- 从系统剪贴板导入图片。
- 保存资产副本。
- 在 Finder 或资源管理器中显示资产。
- 暂停或恢复视频任务跟踪。

拖拽文件由 Preload 使用 Electron `webUtils.getPathForFile` 取得路径并直接交给 Main；路径不返回 Renderer。剪贴板截图由 Main 使用 Electron clipboard API 读取并落盘。

### 5.3 Main 媒体资产服务

媒体资产服务负责：

- 数量和大小校验。
- 真实 MIME 探测。
- SHA-256。
- 安全文件名与目录。
- 临时写入和原子提交。
- 资产元数据持久化。
- 会话删除与崩溃恢复。
- 保存副本和在系统文件管理器中显示。
- 为模型请求读取和编码本地资产。

### 5.4 模型能力路由

聊天服务根据以下信息决定调用路径：

- 当前供应商。
- 当前模型。
- 模型输入和输出模态。
- 用户选择的输出类型。
- 附件类型。
- 生成参数。

路由结果：

- 文本和媒体理解：Chat Completions。
- 图片生成：Images API；Chat 图片输出归一化为同一种本地图片资产事件。
- 音频输出：Chat Completions 的 `modalities` 与 `audio` 参数。
- 视频输出：Videos API 的提交、轮询和下载。

### 5.5 安全媒体协议

注册 `autoforge-media://asset/<assetId>`：

- 只接受合法资产 ID。
- Main 每次请求重新查询数据库和资产状态。
- 文件路径由数据库相对路径和受控媒体根目录组合。
- 支持音频和视频 Range 请求。
- 不接受 Renderer 提供的任意路径。
- CSP 仅增加该受限媒体协议，不开放 `file:` 或通配远程媒体源。

## 6. 数据模型

### 6.1 `media_assets`

新增表，字段包括：

- `id`
- `conversation_id`
- `source`：`upload | generated`
- `kind`：`image | audio | video`
- `mime_type`
- `original_name`
- `relative_path`
- `byte_size`
- `width`（非图片可为空）
- `height`（非图片可为空）
- `duration_ms`（无可用时长时可为空）
- `sha256`
- `provider`（上传资产为空）
- `model`（上传资产为空）
- `status`：`staging | ready | failed | deleting`
- `created_at`
- `updated_at`

约束：

- `relative_path` 必须位于受控媒体根目录下。
- `ready` 资产必须有文件、MIME、字节数和哈希。
- 资产通过 `conversation_id` 级联删除。
- 绝对路径、Base64 和远程下载 URL 不入库。

### 6.2 `media_generation_jobs`

新增表，字段包括：

- `id`
- `conversation_id`
- `assistant_message_id`
- `provider`
- `model`
- `kind`：本期固定为 `video`
- `provider_job_id`
- `status`：`pending | in_progress | downloading | paused | completed | failed`
- `parameters_json`
- `next_poll_at`
- `poll_attempts`
- `error_code`
- `asset_id`（完成前为空）
- `created_at`
- `updated_at`
- `ended_at`

仅保存供应商任务 ID，不保存供应商返回的任意轮询或下载 URL。OpenRouter 任务使用固定官方端点和经过校验的任务 ID 重新构造请求。

### 6.3 消息块

新增两种持久化消息块：

1. `media`
   - `blockId`
   - `assetId`
   - `kind`
   - `purpose`：`input | output`
   - 不可变展示元数据：名称、MIME、字节数、宽高或时长

2. `media_generation`
   - `blockId`
   - `jobId`
   - `kind`
   - `status`
   - 安全错误码（失败时）

新增块更新事件，通过稳定 `blockId` 更新生成状态。视频完成后，同一块转换为最终 `media` 块，避免重复插入和位置跳动。

## 7. 文件布局与生命周期

媒体根目录：

```text
<dataDirectory>/media/
  <conversationId>/
    .staging/
    <assetId>.<safe-extension>
  .quarantine/
```

### 7.1 导入

1. Main 校验会话和附件数量。
2. 在 `.staging` 中创建随机文件。
3. 按流复制并执行字节硬上限。
4. 根据内容探测 MIME。
5. 校验允许的媒体类型。
6. 计算 SHA-256 和基础媒体元数据。
7. 写入资产记录。
8. 原子改名并标记 `ready`。

发送前移除的草稿附件立即删除。启动时清理无消息引用的残留草稿和超时 `.staging` 文件。

### 7.2 生成输出

图片和音频：

- 输出先写入 `.staging`。
- Base64 输出先检查编码长度，再分块解码到文件。
- URL 输出通过安全下载器流式落盘。
- 完成 MIME、大小和完整性校验后原子提交。

视频：

- 提交后立即创建任务记录和生成中消息块。
- 按 `next_poll_at` 轮询。
- 完成后从固定 OpenRouter 内容端点流式下载。
- 校验完成后写入资产，并将生成块转换为媒体块。
- 应用重启后继续 `pending`、`in_progress` 和 `downloading` 任务。

### 7.3 删除与恢复

删除会话：

1. 将会话媒体目录原子移动到 `.quarantine`。
2. 在数据库事务中删除会话、消息、资产和生成任务。
3. 清理隔离目录。

启动恢复根据数据库权威状态处理：

- 数据库会话存在而目录被隔离：恢复目录。
- 数据库会话已删除：清理隔离目录。
- `ready` 资产文件缺失：标记失败并显示安全错误。
- 孤立临时文件：删除。

“清除全部本地数据”包含媒体目录、媒体资产和生成任务，但继续保留 API Key、设置、授权和工作流。

## 8. 模型能力与默认模型

### 8.1 `ModelInfo`

增加：

- `inputModalities`
- `outputModalities`
- `generationCapabilities`
- 支持的图片参数
- 支持的音频格式和音色
- 支持的视频分辨率、画幅、时长和伴随音频能力

OpenRouter 模型发现合并：

- 通用 Models API。
- Images Models API。
- Videos Models API。
- 音频输出能力。

能力合并以模型 ID 为键，端点实际能力优先于模型级能力联合值。

### 8.2 默认模型迁移

默认模型改为供应商与输出类型二维结构：

```ts
{
  deepseek: { text: string },
  openrouter: {
    text?: string,
    image?: string,
    audio?: string,
    video?: string
  }
}
```

现有字符串默认模型迁移到相应供应商的 `text` 槽位。媒体默认模型初始为空，用户选择兼容模型后保存。

### 8.3 自动选择

- 纯文本模型选择文本。
- 主要图片模型选择图片。
- 音频或视频专用模型选择对应类型。
- 多输出模型先使用会话上次选择。
- 多输出模型首次使用时要求用户选择一次。
- 切换输出类型后只展示兼容模型。

## 9. 输入与请求构造

`chat.send` 扩展为：

- 文本内容。
- 资产 ID 列表。
- 输出类型。
- 生成参数。

Main 在发送前重新验证：

- 资产归属当前会话。
- 状态为 `ready`。
- 文件存在且仍在媒体根目录。
- MIME 和大小符合限制。
- 模型支持所有输入模态和目标输出模态。

请求体在 Main 内构造。图片、音频和视频的 Base64 仅存在于供应商请求生命周期中，不通过 IPC 返回。

## 10. Renderer 交互

### 10.1 自适应工具栏

- 附件按钮。
- 拖拽区域。
- 粘贴图片。
- 输出类型选择。
- 当前输出类型的参数摘要与设置弹层。
- 兼容模型下拉框。
- 附件卡片和发送前校验信息。

### 10.2 图片

- 一张图片使用单图卡片。
- 多张图片使用响应式网格。
- 支持查看大图、保存副本、在文件管理器中显示。
- 生成时显示占位状态；只持久化最终图片，不持久化局部预览帧。

### 10.3 音频

- 使用本地协议和原生音频控件播放。
- 展示格式、时长和大小。
- 支持保存副本和在文件管理器中显示。
- 本期不生成音频波形数据。

### 10.4 视频

- 生成中块显示 `pending / in_progress / downloading`。
- OpenRouter 未提供可靠百分比时使用不确定进度，不伪造百分比。
- “暂停跟踪”只停止本地轮询，并明确提示上游任务可能继续执行和计费。
- 可继续跟踪。
- 完成后原位置显示原生视频播放器。
- 支持保存副本和在文件管理器中显示。

### 10.5 失败

每个媒体块独立失败。已经成功的文本或其他媒体不被失败块覆盖。失败块提供安全说明和适用时的重试入口。

## 11. 错误处理

新增安全错误类型：

- 媒体类型不支持。
- 附件数量超限。
- 附件或单次请求大小超限。
- MIME 不匹配。
- 文件导入失败。
- 资产丢失或损坏。
- 磁盘空间不足。
- 模型模态不兼容。
- 供应商媒体生成失败。
- 媒体下载失败。
- 视频任务超时。

供应商原始错误体不进入 Renderer。现有鉴权、权限、限流和供应商可用性错误映射继续复用。

## 12. 远程媒体安全

供应商返回的 URL 视为不可信：

- 仅允许 HTTPS。
- 限制重定向次数。
- 每次重定向重新校验。
- DNS 解析后阻止环回、链路本地、私有网段和保留地址。
- 限制连接、首字节和完整下载超时。
- 同时检查 `Content-Length` 和实际流式字节数。
- 下载内容必须通过 MIME 探测。
- 错误响应正文只做有界、安全诊断，不持久化敏感内容。

## 14. 验收标准

- Renderer、IPC 和消息 JSON 中不存在媒体 Base64 或真实文件路径。
- 关闭原始文件后，已导入附件仍可在会话中使用。
- 删除会话后，其媒体目录、资产记录和视频任务均被删除。
- 应用重启后，进行中的视频任务继续跟踪。
- 音视频支持进度拖动和 Range 请求。
- 不兼容供应商、模型或模态在本地失败且不发送请求。
- 超限、伪造 MIME、SSRF 和路径穿越测试通过。
- 文本、工作流和现有供应商切换行为无回归。

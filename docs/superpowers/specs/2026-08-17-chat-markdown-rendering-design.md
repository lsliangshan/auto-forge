# Chat Markdown Rendering Design

## Goal

Render every chat text block as safe Markdown, including fenced code blocks such as ` ```ts `, with syntax highlighting and readable chat-oriented styling.

## Scope

This change affects only the desktop renderer's chat text presentation layer. It applies to text blocks in both user and assistant messages. Message storage, streaming assembly, provider contracts, IPC, and database records remain unchanged.

## Rendering Architecture

Add a small Markdown rendering module beside the chat components. It owns one configured `markdown-it` instance and exports a function that converts a text block into HTML.

The renderer will:

- enable standard Markdown structures, including headings, paragraphs, emphasis, links, lists, blockquotes, tables, inline code, and fenced code blocks;
- preserve chat-friendly line breaks;
- disable raw HTML so user- or model-provided tags are escaped instead of interpreted;
- pass fenced code to `highlight.js` when the declared language is supported;
- escape and render unsupported or missing languages as plain code;
- emit stable language and Highlight.js classes for styling and tests.

`MessageBlock.vue` will use the renderer only when `block.type === 'text'`. Other block types and their current rendering paths are unaffected. The Markdown result will replace the current interpolation-based plain-text paragraph.

## Syntax Highlighting

Register a focused set of common chat and development languages: TypeScript, JavaScript, JSON, shell, Python, HTML/XML, CSS, SQL, YAML, and Markdown. Highlight.js language aliases, such as `ts`, `js`, `sh`, `py`, `html`, and `md`, will remain available through those registrations.

An unknown language identifier must not fail rendering. Its content remains escaped and appears as an ordinary fenced code block.

## Security

Raw Markdown HTML is disabled. Inputs such as `<script>`, `<iframe>`, inline event handlers, and arbitrary HTML elements are displayed as text rather than inserted as live elements.

The implementation will rely only on HTML generated by the configured Markdown parser and escaped output from the syntax highlighter. It will not introduce custom raw-HTML passthrough or broaden Electron navigation privileges.

## Presentation

Chat Markdown styles will be scoped to the message component and will cover:

- compact paragraph and heading rhythm;
- properly indented lists;
- bordered blockquotes;
- scrollable tables and fenced code blocks;
- visually distinct inline code;
- a dark, readable fenced-code surface with preserved indentation and line breaks;
- wrapping for normal prose and horizontal scrolling for long code lines.

The existing message width and chat layout remain unchanged.

## Testing

Use test-driven development in the existing chat component test suite:

1. Add a failing test proving headings, emphasis, lists, and inline code become semantic HTML.
2. Add a failing test using a TypeScript fenced block matching the reported format; verify the fence markers disappear, whitespace is preserved, a `<pre><code>` structure is emitted, and syntax-highlight classes appear.
3. Add a failing security test proving raw HTML is escaped and no executable element is created.
4. Add a failing fallback test proving unknown fenced languages still render escaped code without throwing.
5. Implement the minimum renderer and styles needed to pass those tests.
6. Run the targeted chat component test, desktop typecheck, and lint. Report unrelated pre-existing failures separately.

## Success Criteria

- Chat text renders common Markdown rather than displaying Markdown markers literally.
- A ` ```ts ` fenced block renders as a styled TypeScript code block with syntax highlighting.
- Code indentation, line breaks, and special characters are preserved.
- Raw HTML cannot create live elements in a message.
- Unknown code languages degrade to plain escaped code.
- Existing non-text chat blocks and message behavior continue to pass their tests.

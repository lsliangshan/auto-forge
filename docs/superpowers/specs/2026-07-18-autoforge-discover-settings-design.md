# AutoForge “发现 + 设置”桌面应用设计规格

日期：2026-07-18  
状态：待用户审阅  
视觉基准：[AutoForge 发现页方向](../../design/autoforge-discover-direction.png)

## 1. 产品目标

首版 AutoForge 是一个用于发现和获取自动化工具的桌面应用，只提供“发现”和“设置”两个菜单。默认打开“发现”页，用户可以浏览、搜索、筛选并查看工具详情；“设置”页用于管理基础偏好和下载第三方工具开发模板。

本阶段不实现流程编排、自动化任务、内置浏览器、运行记录、登录、工具发布或远程市场后台。界面中的工具目录由本地数据适配器提供，后续接入真实接口时不改动页面结构。

## 2. 用户闭环

1. 用户启动应用，直接进入“发现”。
2. 用户通过搜索或分类筛选定位工具。
3. 用户查看工具简介、版本、兼容平台和状态。
4. 用户进入工具详情，确认权限信息并执行本地模拟安装。
5. 用户在“设置”中选择目录并下载完整工具模板。

## 3. 信息架构

应用导航严格限制为两项：

- 发现：默认首页，承载工具浏览、搜索、分类、详情和安装状态。
- 设置：承载外观、下载目录、工具模板下载和应用信息。

分类“全部、数据采集、内容发布、效率工具、开发者工具”属于发现页内容筛选，不属于应用菜单。

## 4. 视觉设计

### 应用框架

- 目标窗口为 1440 × 1024，最小窗口为 1080 × 720。
- 顶部使用约 68px 的自定义标题栏，包含产品标识和窗口控制。
- 左侧导航宽约 210px，仅显示“发现”和“设置”。
- 主内容区最大宽度约 1120px，保持充足留白。
- 发现页采用“精选推荐 + 分类筛选 + 连续工具列表”的结构。

### 视觉语言

- 暖白背景、石墨色文字、钴蓝色主操作，少量珊瑚色用于热门标记。
- 正文基准为 14px，页面标题为 34–40px，使用系统中文无衬线字体栈。
- 使用 Element Plus 图标或 Lucide 图标，不使用 emoji、手绘 SVG 或装饰性占位图。
- 信息分组优先使用留白、排版与分隔线；避免仪表盘卡片堆叠和多层阴影。
- 工具图标使用可替换的本地图片资产；缺失资源时使用统一的 Element Plus 图标容器。

## 5. 发现页

### 页面结构

- 标题：“发现自动化工具”。
- 搜索：按工具名称、应用场景或开发者过滤，支持 `Cmd/Ctrl + K` 聚焦。
- 精选推荐：展示一个重点工具的名称、简介、能力标签、开发者、版本、兼容平台和“查看详情”操作。
- 分类筛选：全部、数据采集、内容发布、效率工具、开发者工具。
- 工具列表：连续表格式列表，展示图标、名称、用途、兼容平台、下载量和安装状态。

### 核心状态

- 加载：列表使用骨架屏，搜索与分类仍可见。
- 正常：展示真实感本地模拟数据。
- 无结果：说明当前筛选无匹配项，并提供“清除筛选”。
- 错误：展示可读错误和“重新加载”。
- 已安装：操作按钮显示“已安装”，不会重复执行安装。

### 工具详情

详情使用抽屉，不新增路由。内容包含工具简介、版本、开发者、兼容平台、权限声明、更新说明和安装按钮。安装为本地模拟流程，包含确认、进行中、成功和失败反馈。

## 6. 设置页

设置页只包含首版必要项：

- 外观：浅色、深色、跟随系统；首版至少完整实现浅色主题，其他选项持久化并可切换基础色值。
- 下载目录：展示当前目录并通过系统目录选择器修改。
- 下载工具模板：用户选择目标目录后，将完整模板目录写入目标位置。
- 应用信息：版本、运行平台和开源许可入口。

下载模板必须保留顶层目录，并包含 `manifest.json`、`package.json`、`tsconfig.json`、`README.md`、`src/index.ts` 和编译后的 `dist/index.js`、`dist/index.d.ts`。

## 7. 技术架构

### 技术栈

- Electron + electron-vite
- Vue 3 + TypeScript + Vue Router + Pinia
- Tailwind CSS + Element Plus
- better-sqlite3
- Vitest + Vue Test Utils
- Playwright Electron
- electron-builder

### 进程边界

Renderer 仅负责界面和瞬时交互状态。Preload 通过类型化白名单暴露工具目录、安装状态、设置和目录选择能力。Main 进程负责 SQLite、文件复制、路径校验和窗口控制。

Electron 窗口启用 `contextIsolation`、`sandbox` 和 `webSecurity`，关闭 `nodeIntegration`。Renderer 不直接使用 Node.js、文件系统或任意 IPC 通道。

### 领域模块

- `catalog`：工具目录、本地搜索、分类和详情。
- `installations`：模拟安装状态与已安装记录。
- `settings`：主题、下载目录和持久化偏好。
- `templates`：目录选择、模板校验和完整复制。
- `database`：迁移、连接与仓储。
- `ipc`：共享契约、输入校验和安全错误转换。

## 8. 本地数据

SQLite 首版包含：

- `schema_migrations`：迁移版本。
- `installed_tools`：工具 ID、版本、安装状态和时间。
- `app_settings`：主题、下载目录等键值设置。

工具目录本身使用只读本地种子数据，不写入数据库。应用启动时完成数据库迁移后再创建主窗口；迁移失败时显示可恢复错误页。

## 10. 错误处理

- IPC 错误统一转换为包含 `code` 和 `message` 的安全对象。
- 搜索、筛选和本地目录读取失败均提供页面内重试，不出现空白窗口。
- 模板下载先校验目标路径和冲突，再复制到独立目录；已有同名目录时不覆盖，提示用户重新选择或确认新名称。
- 数据库写入使用事务；安装失败不留下“已安装”脏状态。

## 11. 测试与验收

- 单元测试覆盖工具筛选、安装状态、设置持久化、路径校验和数据库迁移。
- 组件测试覆盖两项导航、搜索、分类、无结果、详情抽屉和模板下载操作。
- Electron 端到端测试覆盖首次启动、发现页默认路由、安装工具、切换设置、选择目录和重启后状态恢复。
- 类型检查覆盖 main、preload、renderer 和共享契约。
- 生产构建与 electron-builder 目录打包通过。

可见验收标准：

- 应用中只出现“发现”和“设置”两个主菜单。
- 1440 × 1024 和 1080 × 720 下无裁切、重叠或不可达操作。
- 用户能完成“搜索工具 → 查看详情 → 安装 → 在设置中下载模板”的完整闭环。
- Renderer 不具备 Node.js 或文件系统直连能力。
- 视觉实现与选定参考图保持一致，并完成同尺寸截图对比。

## 12. 首版边界

首版不实现远程市场接口、账号系统、支付、评论、工具发布、自动更新、流程执行、内置浏览器或云同步。工具安装为可持久化的本地模拟状态；模板下载为真实文件操作。

# 设置页菜单选中态与滚动同步设计

## 目标

设置页左侧菜单始终标识右侧当前模块。点击菜单和手动滚动右侧内容区使用同一选中状态，避免菜单高亮与实际阅读位置不一致。

本设计是 `2026-08-17-settings-section-navigation-design.md` 的增量设计，并替代其中“不增加当前模块高亮或滚动监听”的约束；已有八项映射、页内平滑滚动和不修改路由的约束保持不变。

## 当前模块判定

- 初次进入设置页时选中“大模型供应商”。
- 正常滚动时，以右侧内容区顶部向下 24px 为判定线，选中最后一个模块顶部已越过该判定线的模块。
- 如果尚无模块越过判定线，保持选中第一个模块。
- 当内容区滚动到底部时，强制选中最后一个“关于 AutoForge”，避免最后一个模块因下方空间不足而永远无法越过判定线。

## 交互与状态

`ContextSidebar.vue` 维护唯一的 `activeSettingsSection` 状态，初始值为 `provider`。

- 菜单按钮在 ID 与当前状态一致时增加 `active` 类，并设置 `aria-current="location"`。
- 点击菜单按钮时，先把当前状态更新为目标 ID，再调用已有的 `scrollIntoView({ behavior: 'smooth', block: 'start' })`。
- 右侧内容区触发 `scroll` 时，按照当前模块判定规则更新相同状态。
- 选中样式沿用现有钴蓝文字和浅蓝背景，不引入新的颜色或设计令牌。

## 监听生命周期

滚动容器继续使用 `WorkbenchLayout.vue` 中唯一的 `.workspace-content`。

- 进入 `settings` 路由时查找滚动容器并绑定被动 `scroll` 监听。
- 离开 `settings` 路由时解绑监听并把选中状态重置为 `provider`。
- `ContextSidebar.vue` 卸载时再次确保解绑。
- 如果容器或设置模块尚未渲染，当前同步操作保持无操作；默认选中态仍可显示，后续点击或滚动会重新计算。

每次滚动最多读取八个模块的位置，无需节流、`IntersectionObserver`、跨组件状态或事件总线。

## 改动边界

仅修改：

- `apps/desktop/src/components/ContextSidebar.vue`
- `apps/desktop/tests/components/workbench.test.ts`

不修改设置业务逻辑、数据访问、右侧模块结构、路由配置或其他页面。

## 验证

组件测试覆盖：

- 初次进入设置页时第一项具有选中样式和 `aria-current`。
- 点击其他菜单项会立即统一选中态并保留既有平滑滚动和路由行为。
- 触发右侧滚动时，选中项按照 24px 判定线切换。
- 滚动到底部时选中最后一项。
- 离开设置页或卸载组件后移除滚动监听。

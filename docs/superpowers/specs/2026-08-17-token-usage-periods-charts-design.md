# Token 用量多周期与图表设计

## 目标

扩展设置页现有“Token 账单”模块，使其同时展示今日、昨日、本周、本月和累计五个统计周期，默认打开今日。每个周期显示明确的起止时间、输入 Token、输出 Token、总 Token、时间趋势、模型分布和精确模型明细。

本次只统计本机当前保留的 `chat_runs` Token 数据，不增加美元费用、云端账单、日期自定义、导出、缓存、定时刷新或 Provider 网络请求。

## 已确认决策

- 周期顺序为今日、昨日、本周、本月、累计，默认今日。
- 全部周期使用本机时区；一周从周一 00:00 开始。
- 今日和昨日按小时展示趋势，本周和本月按自然日展示，累计按自然月展示。
- 折线图包含输入、输出、总 Token 三条线。
- 柱状图按模型展示堆叠柱，输入和输出为两个分段，柱高等于总 Token。
- 页面采用上下串联布局：周期与范围、数字卡、折线图、柱状图、模型明细表。
- 一次 IPC 返回五个周期的完整快照，切换页签时不重新查询。
- 图表采用按需引入的 ECharts，不手写坐标系和 Tooltip。

## 统计口径

应用服务在每次 `getTokenUsage()` 调用开始时只捕获一次 `now`，由该时间派生全部周期边界，避免同一个响应跨越小时、日期、周或月边界后产生不一致。

五个周期按半开区间统计：

- 今日：`[今日 00:00, now)`。
- 昨日：`[昨日 00:00, 今日 00:00)`。
- 本周：`[本周一 00:00, now)`。
- 本月：`[本月 1 日 00:00, now)`。
- 累计：`[最早一条有 Token 的保留记录时间, now)`。若不存在有 Token 的记录，起止时间均为 `now`。

时间边界均按 Main 进程所在操作系统的本机时区计算。边界生成和时间桶递增使用本地 `Date` 日历运算，不用固定 24 小时毫秒数推算自然日，因此保留夏令时切换日的正确小时数。

沿用现有 Token 纳入规则：

- `input_tokens` 或 `output_tokens` 至少一个非空时纳入，不限制调用状态。
- 单侧缺失按 `0` 统计；双侧均缺失时不计入。
- `totalTokens` 始终等于 `inputTokens + outputTokens`。
- 模型明细按总 Token 降序，同量按模型 ID 升序。
- 清除会话会级联删除对应调用，下一次刷新自然反映删除后的结果。

## 趋势时间桶

- 今日：从今日 00:00 到当前小时的连续本地小时桶。
- 昨日：覆盖昨日完整自然日的连续本地小时桶。
- 本周：从周一到今天的连续自然日桶。
- 本月：从本月 1 日到今天的连续自然日桶。
- 累计：从最早有 Token 记录所在自然月到当前自然月的连续自然月桶；首桶的实际统计起点仍是最早记录时间，不向前计入该月更早的数据。

没有调用的桶补零，以保持折线连续。无任何累计数据时累计趋势为空；其他周期即使合计为零，也可以在数据层保留连续零值桶，但 UI 根据周期总量显示统一空状态而不渲染无意义图形。

每条调用只进入对应的一个趋势桶。趋势桶合计、模型合计和周期汇总必须完全一致。

## 共享数据契约

保留现有 `ModelTokenUsage`，新增趋势点并扩展周期和快照结构：

```ts
interface TokenUsageTrendPoint {
  startedAt: string
  inputTokens: number
  outputTokens: number
  totalTokens: number
}

interface TokenUsagePeriod {
  startedAt: string
  endedAt: string
  inputTokens: number
  outputTokens: number
  totalTokens: number
  models: ModelTokenUsage[]
  trend: TokenUsageTrendPoint[]
}

interface TokenUsageSnapshot {
  generatedAt: string
  today: TokenUsagePeriod
  yesterday: TokenUsagePeriod
  week: TokenUsagePeriod
  month: TokenUsagePeriod
  allTime: TokenUsagePeriod
}
```

`startedAt` 和 `endedAt` 描述统计范围；昨日的 `endedAt` 是今日 00:00 的排他边界。`generatedAt` 是本次快照唯一的 `now`。Renderer 在展示昨日范围时把排他结束边界格式化为昨日 23:59，其他进行中周期把 `endedAt` 展示为当前时间。

Zod 契约必须验证：

- 所有时间均为合法 ISO 时间戳，周期起点不晚于终点。
- 所有 Token 值均为非负安全整数。
- 每个模型和趋势点的总量等于输入加输出。
- 模型 ID 在单个周期内唯一。
- 趋势点按时间严格递增且不重复，并落在对应周期范围内。
- 模型合计、趋势合计和周期汇总三者一致。

`settings.getTokenUsage(): Promise<TokenUsageSnapshot>` 方法和 IPC channel 名称保持不变，只更新内部响应结构。Main、Preload、Renderer 在同一个桌面应用版本中同步发布，因此不增加旧响应兼容层。

## 数据访问与应用服务

Main 应用服务负责：

1. 捕获一次 `now`。
2. 按本机时区计算今日、昨日、本周、本月边界。
3. 调用 `chatRuns` Repository 获取累计最早时间、五周期模型聚合和各粒度趋势聚合。
4. 补齐连续的本地小时、自然日和自然月时间桶。
5. 将内部毫秒时间戳转换为 ISO 字符串并组装共享快照。

Repository 负责在 SQLite 中聚合，不把原始 `chat_runs` 返回给 Renderer，也不决定 UI 文案。现有 `summarizeTokenUsage(monthStartedAt)` 会改为接收一次查询所需的固定周期边界，并返回五周期的模型汇总与稀疏趋势聚合。实现可以使用少量同步聚合查询；目标是保持一次 IPC 和一致快照，不强求把所有统计压入一条难以维护的 SQL。

不新增数据库表、迁移、物化统计表或持久化缓存。当前数据源和写入目标仍只有 SQLite `chat_runs`；图表数据是读取时派生结果。

## Renderer 状态与数据流

Settings Store 继续维护一份 `TokenUsageSnapshot`、独立加载状态、独立错误和请求版本号。进入设置页或点击刷新时获取完整快照；清除会话或全部数据成功后重新获取。

周期选择属于 `BillingUsagePanel.vue` 的局部 UI 状态，类型为：

```ts
type TokenUsagePeriodKey = 'today' | 'yesterday' | 'week' | 'month' | 'allTime'
```

默认值是 `today`。页签切换只从已加载快照读取对应周期，不发 IPC，不写 Store，也不产生加载闪烁。刷新时保持当前页签和上一次成功快照，新的成功结果到达后原位更新。

数据链路为：

```text
chat_runs
  → Repository 聚合
  → Main 计算边界并补齐时间桶
  → 受认证 IPC 与 Zod 输出校验
  → Settings Store
  → BillingUsagePanel
  → 两个独立图表组件与明细表
```

## 界面布局与交互

模块按以下顺序纵向排列：

1. 标题“Token 账单”、本机数据来源说明和刷新按钮。
2. 今日、昨日、本周、本月、累计五个页签。
3. 当前周期的本地化起止时间。
4. 输入 Token、输出 Token、总 Token 三张汇总卡片。
5. 全宽 Token 趋势折线图。
6. 全宽模型用量堆叠柱状图。
7. 现有模型明细表。

五个周期都显示范围。昨日显示完整自然日的 `00:00—23:59`；今日、本周、本月和累计显示统计起点到快照生成时间。累计无数据时显示“暂无保留记录”。

折线图：

- 三条序列分别为输入、输出、总 Token。
- 横轴按周期使用小时、日或月标签。
- Legend、Tooltip 和数字格式保持三条序列一致。
- Tooltip 显示时间桶范围及三项精确数值。

柱状图：

- 每个模型一根竖向堆叠柱。
- 输入与输出使用与折线图一致的颜色，堆叠高度代表总量。
- 模型名允许截断，Tooltip 显示完整 ID 和输入、输出、总量。
- 模型较多时启用横向 DataZoom/滚动，不丢弃低用量模型。

模型明细表继续保留，提供精确数值、稳定排序和无障碍替代信息。Token 数字使用 `zh-CN` 千位分隔。

## 图表组件边界

- `BillingUsagePanel.vue`：管理页签，渲染时间范围、数字卡、错误/空状态和明细表，向图表传入已选择周期的数据。
- `TokenUsageLineChart.vue`：把趋势点转换为 ECharts 折线配置，管理图表初始化、`setOption`、`ResizeObserver` 和销毁。
- `TokenUsageBarChart.vue`：把模型汇总转换为堆叠柱配置，管理 DataZoom、更新、ResizeObserver 和销毁。

两个图表组件只接收已验证数据，不读取 Store、不调用 IPC，也不自行决定周期边界。ECharts 按需注册 LineChart、BarChart、GridComponent、LegendComponent、TooltipComponent、DataZoomComponent 和 CanvasRenderer，避免引入不使用的图表类型。

## 视觉与响应式规则

- 图表沿用设置页现有表面色、边框、圆角和文字层级。
- 输入、输出、总量在汇总卡、Legend、Tooltip 和图形中使用稳定一致的颜色。
- 两张图始终上下排列并占满内容宽度，不在大屏改为并排。
- 小屏时三张汇总卡改为单列；图表保持最小可读高度并通过 DataZoom 处理横向密度。
- 图表容器尺寸变化时调用 `resize()`，卸载时调用 `dispose()` 并断开 observer。

## 加载、空状态与错误处理

- 第一次加载且无快照时显示“正在加载 Token 用量…”。
- 刷新已有快照时保留数据，只让刷新按钮进入加载态。
- 周期总量为零时数字卡显示 `0`，图表与表格区域显示“暂无 Token 用量记录”。
- 查询失败时只在账单模块显示安全错误，保留上一次成功快照和刷新入口。
- 较旧请求的成功或失败不能覆盖较新的账单结果。
- ECharts 初始化或更新不得改变账单数据；组件卸载后不保留 window 监听器、observer 或图表实例。

## 方案比较与选择

### 采用：完整快照 + 按需 ECharts

一次读取即可在五个周期间即时切换。ECharts 提供成熟的坐标轴、Tooltip、Legend、DataZoom 和响应式生命周期；通过模块化引入控制依赖范围。桌面本地 IPC 的快照体积相对有限，减少交互请求比按页签拆分更简单可靠。

### 未采用：原生 SVG

可以避免新依赖，但需要自行实现坐标比例、标签避让、Tooltip、ResizeObserver 行为和无障碍细节。对于同时存在折线图、堆叠柱和 DataZoom 的需求，定制代码和长期维护成本更高。

### 未采用：按周期请求

单次响应更小，但页签切换会新增加载态、重复 SQLite 查询、竞态和错误状态。当前统计均来自本机 SQLite，且五个周期共享同一数据源，一次一致快照更符合现有模块。

## 测试与验证

### 共享契约

- 接受五周期有效快照。
- 拒绝负数、非整数、非安全整数、非法范围和非法 ISO 时间。
- 拒绝重复/乱序/越界趋势点和重复模型。
- 拒绝模型、趋势与周期三层总和不一致。

### Repository

- 正确区分今日、昨日、本周、本月、累计边界。
- 周一 00:00 进入本周，昨日的今日 00:00 结束点不进入昨日。
- 覆盖跨月、跨年、单侧 Token 缺失、零 Token、失败和取消记录。
- 正确聚合小时、日、月趋势并保持模型稳定排序。
- 清除会话后统计减少，空数据库返回零汇总。

### 应用服务

- 同一个响应只使用一次捕获的 `now`。
- 本地周一、月初、今日和昨日边界正确。
- 本地日历递增能够处理夏令时切换日，不假设一天固定 24 小时。
- 连续时间桶补零，累计空数据范围和趋势正确。

### Store 与界面

- 默认今日，五个页签显示对应范围、汇总、趋势和模型。
- 页签切换不发 IPC，刷新保持当前页签。
- 旧响应不能覆盖新响应，失败保留上次快照。
- 首次加载、刷新、空数据和模块独立错误状态正确。
- 时间与 Token 格式正确，模型表完整保留。

### 图表组件

- 折线图生成输入、输出、总量三条序列。
- 柱状图生成输入/输出堆叠柱，并在模型较多时启用 DataZoom。
- 数据更新调用 `setOption`，容器变化调用 `resize`，卸载调用 `dispose`。
- Tooltip 和图例使用完整模型名、时间范围及千位分隔值。

### 完成验证

运行聚焦测试、桌面端完整测试、TypeScript/Vue 类型检查、生产构建和 `git diff --check`。最后启动 Electron，进入设置页验证默认今日、五周期切换、时间范围、两张图、明细表、空状态和刷新行为。

## 最小改动范围

- 修改共享 Token 用量 Schema、类型和相关契约测试。
- 修改 `chatRuns` Repository 聚合接口及数据库测试。
- 修改应用服务的周期边界和快照装配及其测试。
- 保持现有 IPC channel 和 Preload 方法，只同步更新响应类型和 mock。
- 修改 Settings Store 测试数据与账单面板。
- 新增两个专用图表组件及测试。
- 在桌面应用依赖中加入 ECharts。

不修改聊天写入流程、数据库 Schema、Provider、身份认证、权限、清理语义或其他设置模块。

## 风险与控制

- **时区和夏令时：** 由单一 Main 时间快照和本地日历边界 helper 负责，使用边界测试锁定。
- **累计跨度较长：** 趋势按月而非按日，控制响应大小；模型明细仍只返回每模型一条聚合记录。
- **模型较多导致拥挤：** 使用 DataZoom 和完整 Tooltip，不截断数据集合。
- **图表生命周期泄漏：** 图表组件封装 observer、resize 和 dispose，并以组件测试覆盖。
- **契约升级影响 mock：** DesktopAPI mock、IPC 响应 Schema 和测试 fixture 在同一实现计划中同步更新。

## 成功标准

- 设置页默认展示今日 Token 用量。
- 今日、昨日、本周、本月和累计五个周期均可即时切换并显示正确数字。
- 每个周期显示明确、符合本机时区的起止时间。
- 折线图正确展示约定粒度的输入、输出、总量趋势。
- 堆叠柱状图正确展示所有模型的输入、输出和总量关系。
- 模型明细表继续提供精确、完整、稳定排序的数据。
- 空数据、刷新和失败不会影响设置页其他模块或丢失上一次成功结果。
- 聚焦测试、完整测试、类型检查、构建、差异检查和 Electron 视觉验证全部通过。

# 设置页模块导航设计

## 目标

设置页左侧菜单与右侧可见模块按相同顺序一一对应。点击菜单项时，页面仍停留在设置路由，并将右侧滚动容器平滑滚动到对应模块。

## 已确认问题

应用使用 Vue Router 的 Hash 历史模式。当前设置菜单使用 `href="#provider"` 一类原生锚点；点击后会覆盖路由 Hash，使 `/settings` 变成未知路由并触发兜底重定向到 `/chat`。

当前右侧共有八个模块，左侧缺少“Token 账单”和“VPN 代理”，且“本地数据”与“已保存授权”的顺序和右侧不一致。

## 设计

### 菜单与模块映射

菜单按右侧实际顺序展示：

1. 大模型供应商 → `provider`
2. 默认模型 → `model`
3. Token 账单 → `billing`
4. VPN 代理 → `proxy`
5. 外观与行为 → `appearance`
6. 本地数据 → `data`
7. 已保存授权 → `permissions`
8. 关于 AutoForge → `about`

### 交互

设置侧栏使用普通按钮，不再使用会修改 URL Hash 的锚点。点击按钮后，根据目标模块 ID 查找设置页中的元素，并调用 `scrollIntoView({ behavior: 'smooth', block: 'start' })`。

该交互不修改 URL，不触发 Vue Router 导航，也不增加当前模块高亮或滚动监听。

### 改动边界

仅修改设置页上下文侧栏及其组件测试。右侧模块现有 ID、设置业务逻辑、数据访问和路由配置均保持不变。

### 异常处理

如果设置数据尚未加载、目标模块尚未渲染，点击不执行滚动，也不产生路由或错误状态变化。正常加载后再次点击即可滚动。

## 验证

组件测试覆盖：

- 左侧八个菜单项的文本与顺序和右侧模块一致。
- 点击指定菜单项会对对应模块调用平滑滚动。
- 点击后当前路由仍为 `/settings`，不会进入 `/chat`。

随后运行设置页相关组件测试、桌面端类型检查，并检查最终差异只包含本需求相关改动。
